1. WHAT SAHKARMI IS
================================================================================
Sahkarmi is a local-first DESKTOP app (Windows, macOS, Linux) where each AI
"coworker" has its own workspace folder, embedded browser, memory and task
queue. It is the same product category as other "AI coworker" desktop apps,
with its own Indian brand and identity.

- It is NOT a website. "Going live" = publishing installers (.exe / .dmg /
  .AppImage) on GitHub Releases for people to download.
- There is no Sahkarmi cloud/server. Coworkers run through AI CLIs on the
  user's own computer:
    * OpenCode     — BUNDLED with Sahkarmi, free models, no login
    * Gemini CLI   (Google)     — command: gemini   (free tier with Google login)
    * Claude Code  (Anthropic)  — command: claude   (user's plan)
    * Codex CLI    (OpenAI)     — command: codex    (user's ChatGPT plan)
  Nothing extra is required: the bundled OpenCode works out of the box.
- Built with: Electron 43, SolidJS, TypeScript, Tailwind 4, Bun 1.3.11,
  Vitest, Biome.

5. PRODUCT FEATURES (WHAT WORKS TODAY)
================================================================================
THREE-PANE LAYOUT
 Left rail (260 px, resizable, collapsible)
  - Brand mark + "Sahkarmi / सहकर्मी"
  - Workspace switcher: switch, create, rename workspaces. Each workspace
    has its own team. Default workspace: "My Business".
  - Team list: avatar, name, role, live status dot:
        grey   = idle
        green  = working (pulses)
        yellow = waiting for you (pending approval, question, take-over)
        red    = needs attention (last task failed / error)
    Right-click a coworker → Edit / Delete.
  - "+ New coworker" (creates, then asks model + specialty)
  - Shared files, Approvals (red badge = pending count), Settings
 Centre
  - Header: coworker avatar, name, role, status; "Browser" toggle
  - Task queue strip: counts of queued / running / done, chips per task,
    Pause / Resume, Cancel (queued), Stop (running), Show all
  - Thread: streamed replies, inline **bold** and `code`, reactions,
    replies, attachments, "Thinking" disclosures
  - Tool-call cards: one line each (icon, name, preview, Running/Done/Failed),
    click to expand input/output
  - Composer: message box, attach file, model picker, voice input,
    "Run on schedule" toggle, send / stop
 Right pane (resizable, collapsible)
  - Coworker's embedded Chromium browser with tabs and an address bar
  - "Take over": the owner drives the browser (login, OTP/2FA, CAPTCHA,
    payment pages). While the owner is in control, coworker browser tools are
    paused and told to wait.
  - "Hand back" (with an optional note to the coworker)
  - Coworkers can REQUEST a take-over; a yellow banner appears and the
    browser opens automatically. On hand-back, the coworker gets a
    "[Browser handed back]" message and continues.
  - Coworker settings panel (name, role, description, avatar, model,
    reasoning level, notifications)

APPROVALS (human in the loop)
 - Coworkers are instructed to call sahkarmi.request_approval and STOP before:
   payments, messages to customers/vendors, publishing, submitting government
   / tax / bank / marketplace forms, deleting data, sharing personal data.
 - Approvals view: coworker, category, amount (₹), details, optional note,
   Approve / Reject, plus history of decided items.
 - The decision is sent back to the coworker as a message
   ("[Approval APPROVED] …" / "[Approval REJECTED] …"), so nothing blocks
   while the owner is away. Approvals survive app restarts.

SCHEDULES ("Run on schedule")
 - Once (date + time), every hour, every day, weekdays (Mon–Fri), weekly.
 - Times use the computer's local time (IST for most users).
 - Runs missed while the app was closed fire once on next launch.
 - Each run queues "[Scheduled task] …" to the coworker.
 - List under the composer: Run now / Disable / Delete.

SHARED FILES
 - Browse ~/Sahkarmi/Shared (folders first), add files (never overwrites,
   adds "(1)"), open, show in folder. Path traversal blocked.

LANGUAGES
 - UI: English, हिन्दी, বাংলা (Settings → Language). The app chrome is
   translated; some deeper upstream strings are still English.
 - Coworker instructions: assume India (₹ lakh/crore, GST, IST, DD/MM/YYYY)

10. RELEASE PIPELINE (GITHUB ACTIONS) EXPLAINED
================================================================================
Trigger: pushing a tag vX.Y.Z (or creating a release with a new tag).
Rules checked: tag must point to a commit on main; package.json version must
equal the tag; CHANGELOG.md must contain "## [X.Y.Z]".

Jobs:
  validate → macos + windows + linux (in parallel) → publish
  macOS   : lint + typecheck + tests → if Apple secrets exist, signed and
            notarized build; otherwise UNSIGNED beta build → launch check
  Windows : checks → unsigned NSIS installer → launch check
  Linux   : checks → AppImage
  publish : uploads everything to the GitHub Release (creates or updates it)

To ship the next version:
  1. Change "version" in package.json (e.g. 0.2.2)
  2. Add "## [0.2.2] - <date>" to CHANGELOG.md
  3. Commit and push to main
  4. Create a release with tag v0.2.2 (as in Section 9, Step 1)

Installed apps auto-update from GitHub Releases (electron-updater). Note: the
macOS auto-update usually only works with SIGNED builds.

12. KNOWN ISSUES AND LIMITATIONS
================================================================================
 1. VOICE INPUT: uses the browser's Web Speech API. Inside Electron this
    often fails without Google speech API keys. The app shows an error
    instead of crashing. Fix later: offline Whisper, or a cloud STT
    (e.g. Google, Azure, Sarvam AI for Indian languages).
 2. UNSIGNED BUILDS: Windows SmartScreen and macOS Gatekeeper warnings on
    first launch. Mac auto-update may not work until signed.
 3. Mac build is Apple Silicon (arm64) only; no Intel Mac build.
 4. The browser is shared: one embedded browser with tabs per coworker.
    Take-over pauses ALL coworkers' browser use, not just one.
 5. Translations cover the app chrome; some deeper upstream strings
    (onboarding, error texts, some menus) are still English.
 6. Full local access: coworkers can read/write files and run commands like
    the CLI they run on. Approvals depend on the model obeying instructions;
    they are not a hard sandbox.
 7. Installer size ≈ 350–400 MB (Electron + Claude Agent SDK + bundled
    OpenCode ≈ 186 MB). Free models come from OpenCode's service; their
    names/availability can change — update OPENCODE_VERSION in
    scripts/fetch-opencode.ts to ship a newer OpenCode.
 7b. OpenCode / Gemini coworkers: Sahkarmi tools work through an HTTP MCP
    bridge; an ACP agent that doesn't support HTTP MCP still chats but can't
    use the Sahkarmi browser/approval tools. Gemini CLI must be installed
    separately (needs Node.js 20+).
 7c. Signed macOS builds: the bundled OpenCode binary may need extra
    hardened-runtime entitlements once Apple signing is enabled — test then.
 8. Linux: when running as root you must pass --no-sandbox (normal users are
    unaffected). desktopName is not set (minor window-grouping warning).
 9. Upstream OpenBot docs (TROUBLESHOOTING.md, PRIVACY.md, SECURITY.md) were
    renamed but not fully rewritten for Sahkarmi — review before a public
    launch.
10. 4 open Dependabot pull requests on GitHub (dependency bumps). Two failed
    CI (upload-artifact v7, download-artifact v8: major-version changes).
    Do not merge those two blindly; the "compatible-updates" one passed.

15. TROUBLESHOOTING
================================================================================
"Release job failed"
   → Actions → open the run → click the red job → screenshot the red step.
"Tag must point to main" error
   → create the release with Target = main.
"Tag does not match package.json version"
   → the version in package.json must equal the tag without the "v".
"CHANGELOG" error
   → add a "## [X.Y.Z]" heading for the version.
App says "AI provider setup required"
   → install Claude Code or Codex, run "claude auth login" / "codex login",
     restart Sahkarmi, then Settings → AI providers & permissions.
Windows: "claude" not found
   → install the native Claude Code CLI and Git for Windows; reopen
     PowerShell; check that "claude --version" works.
Coworker stuck "Waiting for you"
   → check Approvals (badge), the browser banner (take-over request), or a
     question card in the thread.
Reset local data (development only)
   → bun run dev:reset
Full app data reset
   → quit Sahkarmi, delete the app data folder (Section 7). Coworker folders
     in ~/Sahkarmi are kept unless you delete them too.
