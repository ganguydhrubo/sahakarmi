# Marketplace coverage: engineering, design, web, industry

Source files: `src/shared/agent-catalog/engineering.ts`, `design.ts`, `web.ts`, `industry.ts`.
Every agent is a `defineAgent({...})` template; its standing brief is generated by `agentBrief()` in `types.ts`.

Status key:
- **Operational**: works with Sahkarmi's built-in tools (Shared files, local commands and code, web research, Sahkarmi's browser with the owner signing in via takeover).
- **Needs setup**: a named outside service must be connected first (`availability: "needs-setup"`).

Coworkers never type passwords, OTPs or secrets. Anything external or irreversible goes through `sahkarmi.request_approval` first.

References used for role scoping:
- O*NET OnLine (onetonline.org) occupation task lists.
- ISCO-08 (ILO International Standard Classification of Occupations). India's NCO-2015 follows the ISCO-08 structure, so the ISCO unit groups below also locate the roles in NCO-2015.
- W3C WCAG 2.2 (W3C Recommendation, 2023) for accessibility.
- OWASP Top 10 for application security.
- Indian rules the industry agents prepare for (they do not file anything): CGST Rules (e-way bill, Rule 138), Income-tax Act s.80G with Form 10BD, the Real Estate (Regulation and Development) Act 2016, and the Digital Personal Data Protection Act 2023.

## 1. Engineering (15 agents)

**What this work is.** Software engineering means turning a business need into working, tested software and keeping it running. That covers requirements, design, coding, databases, testing, security, release and documentation (O*NET 15-1252 Software Developers, 15-1253 Software QA Analysts and Testers; ISCO-08 251x Software and applications developers and analysts, 2521 Database designers and administrators). For an Indian small business the typical jobs are a website or internal tool, an integration (Razorpay, WhatsApp, Tally exports), a bug in an existing app, or taking over a project a freelancer left behind. All of it is computer work: the repo sits on the owner's PC or GitHub, and hosting is a web console the owner signs in to.

### Software Engineering Team coordination protocol

`software-engineering-team` is the featured coordinator. It has the `delegation` and `code` capabilities and works like this:

1. **Requirements and baseline.** It writes numbered requirements with acceptance criteria, inspects the repo (stack, scripts, tests) and runs the existing tests so there is a recorded baseline to compare against.
2. **One authoritative plan file.** It keeps `Shared/Engineering/<project>/PLAN.md` with the architecture, task IDs, the owner coworker of each task, the paths each owner may change, dependencies and status. This is the only plan. Each specialist updates only its own rows.
3. **Only the roles needed.** It chooses from CTO/tech lead, product analyst, UI/UX, frontend, backend, database, security, QA, DevOps and technical writer. It reuses existing coworkers found with `sahkarmi.list_agents`, or makes new ones with `sahkarmi.create_coworker`. It briefs each one with `sahkarmi.send_message`: task IDs, owned paths, paths not to touch, branch name, and the evidence it expects back.
4. **Ownership boundaries.** Tasks run in parallel only when their owned paths do not overlap. Shared files such as `package.json`, the DB schema and the route table each get one owner, and other coworkers send that owner change requests.
5. **Integration and review.** It merges branches one at a time, then runs the full build, lint and tests. The security and QA coworkers review the integrated build and run regression tests on it.
6. **Release prep.** It updates the README and CHANGELOG and prepares the version, migrations and rollback plan. Merging to main and deploying wait for approval.
7. **Live verification.** After an approved deploy it checks every acceptance criterion on the live URL and records the results in PLAN.md.

**Evidence rule.** A task counts as complete only when it has evidence: test or build output, a commit hash, a PR link or a URL. The coordinator's own validation also checks that no two coworkers changed the same file unless the plan allowed it, and that the integrated suite matches or beats the baseline.

- *UI/UX* for engineering projects is covered by `ui-ux-designer` in the design category. The coordinator can create that coworker, so there is no duplicate.
- *Mobile app developer* is not separate. Frontend and full-stack cover React Native/PWA work; store publishing would be an approval step under DevOps.
- *Data engineer / ML engineer* is left out of this category. Analytics work belongs to the research/finance helpers, and ML-specific pipelines are rare for the target SMBs.

## 2. Design (13 agents)

**What this work is.** Design and media work produces the things customers see and hear: screens, websites, brand kits, creatives, decks, videos and audio (O*NET 27-1024 Graphic Designers, 15-1255 Web and Digital Interface Designers; ISCO-08 2166 Graphic and multimedia designers). On a computer it means research and references, specs and prototypes (HTML/CSS), files built with code (pptx, ffmpeg, image resizing), and checking work against a spec. The agents produce finished files where a local tool can (HTML prototypes, .pptx, ffmpeg cuts, SRT). Where only a human designer or an outside model can produce the work, they write precise briefs.

## 3. Web (11 agents)

**What this work is.** Web work keeps a business's website and online portals useful: auditing and fixing sites, updating CMS content, testing, accessibility, SEO, migrations, analytics, and the many repetitive "do this on that portal" jobs (O*NET 15-1254 Web Developers, 15-1299.01 Web Administrators; ISCO-08 2513 Web and multimedia developers, 3514 Web technicians). In practice, for an Indian SMB, it means a WordPress or Shopify admin, Google Search Console and GA4, IndiaMART/JustDial enquiries and government or supplier portals. All of these run in Sahkarmi's browser with the owner's own sign-in.

## 4. Industry (10 agents)

**What this work is.** These are the office and paperwork roles that sit inside a specific Indian industry, where the work is done on a computer but needs sector vocabulary and documents: clinic front office (ISCO-08 3344 Medical secretaries, 4226 Receptionists), real-estate broker office (3334 Real estate agents and property managers), dispatch and transport clerks (4323 Transport clerks), production planning (4322 Production clerks), quantity surveying and site office (O*NET 13-1051 Cost Estimators), hotel front desk (4224 Hotel receptionists), consulting proposals (O*NET 13-1111 Management Analysts, support tasks only), school and coaching office (3343 Administrative and executive secretaries), NGO administration (O*NET 13-1131 Fundraisers), and a CA practice office. Every agent stops short of regulated judgement: no medical advice, no legal title opinion, no filing without the professional.
