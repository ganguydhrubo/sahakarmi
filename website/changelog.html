Version 0.12.3 26 October 2026

Fixed

  • "Update now" for Claude Code and Codex works. It used to run npm install -g, which updated a copy Sahkarmi did not use (Claude's own installer puts its claude.exe first, so the version never changed) and failed with "a file of the tool is in use" while a coworker was running the tool. Now Sahkarmi downloads its own copy from npm into a new folder for each version, checks npm's checksum and the program's version, and switches to it when your coworkers are not busy. It always uses the newer copy: its own or yours. Your own installs are never changed. With automatic updates allowed, this happens by itself, like the OpenCode runtime.
  • The built-in browser no longer reloads tabs in a loop. When a coworker kept working on a site (for example Google Search Console with many tabs open), the tab you were looking at reloaded after every one of its clicks, and broken links showed a 404 again and again. Now a tab is reloaded only after the coworker has been quiet for 5 seconds, at most once every 30 seconds, never when it shows an error page, and never when a coworker has typed in it and not saved.

Version 0.12.2 26 October 2026

Fixed

  • Updates no longer start again and again with "Retry". Opening Sahkarmi while an update was still installing blocked the installer, threw away the finished download, downloaded it again and kept failing because Windows was still using the file. Now a finished download is kept, a file that is in use is not retried every few seconds, and if an update is installing when you open Sahkarmi, it says so, closes, and opens by itself when the install is done.

Version 0.12.1 26 October 2026

Fixed

  • Codex coworkers whose chat started before an update now get the new tools by themselves. Codex cannot add tools to a running chat, so on the next message Sahkarmi starts a fresh chat for the coworker and gives it the latest part of the earlier conversation. You still see the whole chat; nothing to do by hand.

Version 0.12.0 26 October 2026

Added

  • Coworkers learn skills as they work. After a task that took several steps, a fix, or a correction from you, a coworker saves the playbook to Shared/Skills/Learned, and later runs improve it (the version goes up, with a note of what changed). Skills never hold passwords, OTPs, keys or card numbers. Marketplace > Skills lists them under "Learned by your coworkers", where you can open or delete each one.
  • Coworkers can search earlier chats (their own, or the whole team's) to recall what was decided, sent or promised, instead of guessing.
  • Chat with your coworkers from Telegram. In Settings > Telegram, open @BotFather from the button, paste the bot token, then tap "Pair in Telegram" and press Start; only that one chat is answered. Your message goes into the coworker's normal queue, Telegram shows "typing..." while it works, and its finished reply comes back to Telegram. A "Show me how" guide walks a first-time user through all 7 steps with a picture for each. /coworkers lists them and /use switches. New approvals are announced there too (you still allow or deny them in the app). Sahkarmi must be open on the computer.

Fixed

  • When a coworker changes a site in one browser tab, your other tabs of the same site no longer show old data: the tab you are looking at reloads a moment after the coworker finishes, and hidden tabs reload when you open them. A tab you typed or clicked in is never reloaded over your work.

Added

  • Send stays available while a coworker works: your message goes into the queue. Esc in the message box stops the coworker, and Send now on a queued message runs it next.
  • Approvals from the keyboard: Enter approves and Esc rejects an approval card in the chat.

Changed

  • Your message shows in the chat at once and the box is ready for the next one.
  • Long chats open fast: the latest 80 messages show first, with "Show earlier messages".
  • Tool rows read as one plain line in English, Hindi and Bengali, and commands show what the coworker ran instead of the PowerShell wrapper.

Fixed

  • Tool calls no longer vanish while a coworker works; the row grows as calls arrive.
  • Streamed text no longer shows twice.
  • Claude coworkers start again on Windows (the npm .cmd shim no longer wins over claude.exe).
  • A chat whose AI tool is not installed opens at once instead of waiting about 6 seconds.
  • On a busy computer, a slow page's file picker no longer slips past and opens the Windows dialog: a coworker's click now watches for it a little longer (400 ms).

Version 0.11.0 26 October 2026

Added

  • Secure password and OTP card: when a site asks for a password, OTP or PIN, the coworker asks for it in a card in the chat. What you type goes straight into that page field (same site only) and is never shown to the coworker, saved or added to the chat. Take over and Decline are on the card too.
  • Browser pages: every open page shows as a small live picture in its own column beside the chat. Click one to open it, X to close it, + for a new page. Pages a coworker is using are outlined.
  • Browser start menu: an empty browser offers Open Browser, Open Files, Open Tasks, Open Agent settings and Open Voice.
  • The browser panel can be dragged wider or narrower, expanded to fill the chat space and restored, or shrunk to the page pictures.
  • Chat follows new messages only while you are at the bottom, scrolls smoothly, and shows a "Get to bottom" button with a new-message dot when you scroll up.
  • Settings > About: meet the founder, Dhrubo, with LinkedIn, Telegram and email, plus Sahkarmi's website, LinkedIn, Facebook and Instagram, with smooth motion.
  • Settings > AI: add more Google accounts for Gemini. When one account reaches Google's limit, Sahkarmi moves to the next and sends the message again.

Changed

  • Gemini starts together with the other AI tools instead of after them, keeps a recent chat warm, and sleeps after 30 minutes without use. Replies on an existing Gemini chat arrive about twice as fast once Gemini is ready.

Fixed

  • Gemini no longer starts twice at launch, and model checks no longer leave helper processes running in the background.
  • The voice note preview shows its real length instead of 0:00.
  • A page a coworker was working on in the background could appear on top of the app, outside the browser panel. Background pages now stay out of sight while coworkers use them.

Version 0.10.0 25 October 2026

Added

  • Settings > Voice: speak instead of typing, on this PC. Download a model once and dictation works offline; your voice never leaves the computer. Models: all 22 scheduled Indian languages (AI4Bharat IndicConformer), Hinglish fast and best (Roman script with punctuation), English fast, and Whisper large-v3 turbo for about 100 languages with a language picker.
  • Spoken replies: Indian voices (AI4Bharat Rasa: Hindi, Bengali, Marathi, Tamil, Telugu and 8 more) and English voices (Kokoro), with four voice choices, Listen, speaking speed, Read aloud in each reply's menu, and an optional "Read replies aloud" for the open chat.
  • The microphone in the message box and on Tasks now writes text live after each pause when a dictation model is installed. A voice note can now be turned into text only.
  • Every download is pinned to a fixed version and checked by SHA-256 before use. Strings in English, Hindi and Bengali.

Version 0.9.2 25 October 2026

Added

  • Marketplace > Apps lists all 1,660 Composio apps with their real logos before you add a key. The key card opens only when you press Connect or Add key.
  • The key card is now a full setup guide: five simple steps with logos and a link to the API Keys page, Platform (ak_) versus Connect (ck_) keys, Full access, a "Something went wrong?" list for every known error, and a safety note. In English, Hindi and Bengali.

Fixed

  • A good Composio key could be refused when it was pasted with quotes, a label such as COMPOSIO_API_KEY=, spaces or hidden characters. Sahkarmi now cleans the paste first.
  • A refused key now says why in plain words: a user key (uak_) instead of the Project API key (ak_), a key Composio calls invalid, or a limited key. The technical "Error invoking remote method" prefix is gone.
  • A Connect key (ck_) is named and explained without being sent. A key with read-only access now says it needs Full access when an app is connected, with a Replace key button.

Version 0.9.1 25 October 2026

Fixed

  • Clicking Connect again while GitHub Copilot was still installing started a second install that failed and left Copilot looking "not installed". A second click now shows the install in progress, and Sahkarmi carries on when the tool did land.
  • GitHub Copilot signs in on its own: with your GitHub CLI sign-in when you have one, otherwise GitHub's page opens and Sahkarmi shows the code to enter there. No console to type in.
  • A failed connect is now written to the app log, so it can be traced.

Version 0.9.0 25 October 2026

Added

  • Marketplace has a new Apps tab. It lists every app Composio offers (GitHub, Gmail, Google Calendar, Slack, Notion, Jira, Linear and many more) with Connect buttons, logos and a search box. Connected apps sit at the top under "Your apps". It runs on Composio's free Hobby plan: $0, no card, 1,00,000 tool calls a month. You paste your own Composio key once; it stays on this computer.
  • Coworkers use your connected apps through your own accounts. Reading is instant. Anything that sends, creates, changes or deletes stops for your approval first; once you approve, the coworker carries out that same action, exactly once.
  • The provider connect screen is rebuilt: brand marks, groups for Connected, Found on this computer and Add a provider, Free badges, and inline install and sign-in progress.
  • 11 more agents over ACP: Cursor, GitHub Copilot, Kimi Code, Cline, Qwen Code, Grok, Factory Droid, Qoder, Goose, Mistral Vibe and Kiro. Connect installs the tool when needed and starts its sign-in; tools already installed are found.
  • Coworkers can create and change routines when you ask them to in chat. Agreeing to "post every day at 6 PM" now creates a real routine instead of only a note.
  • Routines from your previous desktop agent are brought over once, paused, on first start, each matched to the coworker with the same name. Its own data is only read, never changed.
  • When OpenCode's free limit is used up, a coworker moves by itself to another free provider you have connected (Gemini, GitHub Copilot or Kiro) and answers your message there.

Changed

  • The Composio section moved out of Business into Marketplace > Apps.
  • Composio is reached through its current API (the old one was switched off). A busy or slow Composio is handled quietly: Sahkarmi waits and retries, never repeats a send or a delete, and pauses for a minute after repeated failures.
  • When OpenCode's free limit is used up, you are told at once instead of waiting about a minute per model.
  • Logos in the model picker and the first-run screen; missing agents read "Not installed".
  • The Routines canvas shows times in your own clock style ("6:00 pm"), an On / Paused badge, arrows between steps and each coworker's role.

Fixed

  • A failed message that is resent automatically no longer shows twice for a moment after an automatic switch to the free model.
  • Composio replies and errors are cleaned of tokens before they reach a chat.

Version 0.7.4 25 October 2026

Version 0.7.3 24 October 2026

It used to pretend to be Firefox on accounts.google.com while everything else about it was Chromium, and Google answered "This browser or app may not be secure". It now presents one plain Chromium identity on every site, and sign-in popups ("Continue with Google", OAuth consent) open as a real popup window that shares the browser's session, so no login flow is blocked.

Version 0.7.2 24 October 2026

Fixed

  • First message on a fresh install came back "Interrupted · Send again" and the coworker stayed "working" with its queue stuck: the CLI/model refresh (every window focus) restarts providers that are not signed in, and that restart marked every other provider's running turn as "Sahkarmi restarted". Only deliveries left over from a previous process are reconciled now, per provider.
  • A coworker on the free model could sit at "working" for ever when OpenCode's free usage limit was reached, because OpenCode's agent never answers in that case. A turn with no sign of life for 60 seconds now fails with a readable reason, and the coworker is free again.
  • "AI tool update failed: EPERM/ENOTEMPTY" after a successful bundled-runtime update on Windows.

Added

  • The free model rotates: "Free model (no login)" tries OpenCode's default model first and then every other free model it offers. When one stops answering (its usage limit is used up), it is skipped for an hour and your message is sent again on the next free model by itself, with a note in the chat.

Changed

  • Windows-only release. The macOS and Linux builds are paused until the project has tested them on real hardware; the website and install guide say so. Installed 0.7.1 macOS and Linux builds keep working but will not find an update until those builds return.

Version 0.6.3 24 October 2026

Version 0.6.2 24 October 2026

Fixed

  • "AI updates" ran npm install -g for Claude Code and Codex again and again (hundreds of times a day) on computers where Sahkarmi uses a copy of the CLI that npm does not own, which also broke the npm shims while it ran: Codex showed "could not be started" and Claude asked to sign in. "Update now" still runs the install for you and then says which copy Sahkarmi actually uses.
  • OpenCode (and Google's agent) showed "Not installed" on a busy or cold disk because --version of the 200 MB binary took longer than the 5-second limit. The limit is 25 s.

Version 0.6.1 24 October 2026

Fixed

  • Stopping a coworker no longer lets the stopped answer stream into the next turn (OpenCode keeps talking after a cancel; the next turn now waits until that stream has gone quiet), and a stopped turn with nothing said leaves no empty bubble.
  • A new message from the owner resumes a queue that Stop had paused, instead of sitting at "Queued #1" until Resume was found.
  • AI tool updates (bundled OpenCode, Codex) failed on Windows with "tar: Cannot connect to C:" when Git's tar was first on PATH. Extraction now runs with relative paths.
  • Google Antigravity: a used-up quota (HTTP 429) used to end the turn with a blank reply and pages of harness chatter in the log. The coworker's chat now says the quota is used up and when it resets, and start-up chatter stays out of the log. Any provider that ends a turn with nothing said now gets a visible "empty reply" note.
  • Sidebar previews show plain text instead of raw markdown marks.
  • What's New shows this release's real changes (and nothing for versions without an entry).

Version 0.6.0 23 October 2026

Changed

  • Google Antigravity now connects the same way as Claude and Codex: Connect downloads Google's own Antigravity agent (agy_acp_server 1.4.2 from dl.google.com, SHA-256 pinned), asks it whether it is signed in, and if not runs its "Log in with Google" sign-in, which opens the Google page in the browser. No terminal window, no separate install. A Google AI Studio API key also works.
  • The Antigravity IDE (Antigravity.exe) is no longer treated as an agent server; this was the cause of "Google Antigravity exited with code 0".

Removed

  • The Gemini CLI provider. Google has moved individual use to Antigravity, and the Gemini CLI sign-in needed a terminal window. Coworkers saved on a Gemini model move to the bundled free model.
