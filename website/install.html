Install Sahkarmi

Current version: 0.7.1. This page says exactly what is built, what is tested, and what to do when something goes wrong. Platform status was last checked by the project on 24 October 2026.

Memory: on the project's test PC (Windows 11, 16 GB RAM) the app used about 1 GB of RAM in total with the bundled free-model runtime running. Disk: allow about 1 GB for the app plus the runtime it downloads. The free models and any provider you connect need an internet connection; nothing runs offline.

Windows

  1. Download the Windows installer (the newest -x64.exe on GitHub Releases).
  2. Open the file. Windows SmartScreen will say "Windows protected your PC" because the installer is not code-signed yet. Click More info, then Run anyway. You can verify the file's checksum first.
  3. The installer runs without further questions and installs for your user only (no administrator rights) under %LOCALAPPDATA%\Programs\sahkarmi, with a Desktop and Start Menu shortcut named Sahkarmi.
  4. Sahkarmi opens by itself after installing.
winget: a manifest for Sahkarmi.Sahkarmi has been submitted to the Windows Package Manager community repository and is waiting for Microsoft's moderation. Until it is accepted, winget install Sahkarmi.Sahkarmi does not work; use the installer above.

macOS

Apple silicon only. The build is produced by GitHub Actions and has not been tested by the project on a Mac for this release; please report what you find.

  1. Download the macOS disk image (the newest -arm64.dmg on GitHub Releases).
  2. Open the DMG and drag Sahkarmi into Applications.
  3. If macOS says the app cannot be opened because it is from an unidentified developer, right-click (or Control-click) Sahkarmi in Applications and choose Open, then confirm. Alternatively open System Settings, Privacy & Security, and allow it there.
  4. The app asks for microphone access only when you press the record button for a voice note.

Linux

An AppImage for x86-64 desktops. Built in CI, not tested by the project on real hardware for this release.

Download the AppImage, then:

chmod +x Sahkarmi-*.AppImage
./Sahkarmi-*.AppImage

If it fails to start with a FUSE error, install your distribution's libfuse2 package (Debian and Ubuntu: sudo apt install libfuse2) or run it with --appimage-extract-and-run. Some distributions also need --no-sandbox when the user namespace sandbox is disabled; prefer fixing the sandbox over using that flag.

Verify the download

Every release attaches SHA256SUMS.txt (all platforms) and per-platform SHA256SUMS-windows.txt, SHA256SUMS-macos.txt and SHA256SUMS-linux.txt, plus a build provenance attestation created by GitHub Actions. Compare the hash of your file with the one on the release page.

Windows (PowerShell)

Get-FileHash .\Sahkarmi-*-x64.exe -Algorithm SHA256

macOS

shasum -a 256 ~/Downloads/Sahkarmi-*-arm64.dmg

Linux

sha256sum Sahkarmi-*-x86_64.AppImage

To check the provenance attestation with the GitHub CLI: gh attestation verify Sahkarmi-<version>-x64.exe --repo ganguydhrubo/sahakarmi.

First launch

  1. Choose your provider. On a clean computer only OpenCode (free, built in) shows as Available; Claude and ChatGPT show "Sign in required" and Google Antigravity "Not installed". Keep OpenCode selected and click Continue with OpenCode (free). You can change this per coworker later.
  2. A short What's New dialog describes this release. Click Got it.
  3. Pick a coworker in the left list (for example Asha, Accounts) and type a message. The first reply on the free model usually takes a few seconds; the first time on a new PC the bundled runtime may also download its newer version in the background.
Free model limits. OpenCode sets a usage limit on each of its free models. If a coworker on the free model stops answering, the limit for that model is probably used up for now: wait and try again, pick another free model from the model menu, or connect your own provider below. Version 0.7.1 can sit at "working" in this case; the next release fails the turn with an explanation after 60 seconds and moves to the next free model by itself.

Connecting an AI provider (optional)

Open Settings, then AI and models. Each provider has a Connect button and an API key option. Your password is only ever typed on the provider's own page; Sahkarmi reuses the sign-in and never copies tokens.

Terminal install and building from source

There is no package in winget, Homebrew, AUR or Flathub yet, so there is no one-line installer. To build from source (any platform with Bun 1.3.11 and Node.js 22.12 or newer):

git clone https://github.com/ganguydhrubo/sahakarmi.git
cd sahakarmi
bun install --frozen-lockfile
bun run fetch:opencode   # downloads the bundled free-model runtime for your platform
bun run dev              # starts the app from source

Installer builds: bun run dist:win on Windows, bun run dist:mac on an Apple silicon Mac, bun run dist:linux on Linux. See the README for the full command list.

Updating

The installed app checks GitHub Releases for updates shortly after launch and then periodically. Under Settings, Updates, you choose whether updates download automatically or ask each time, and you can check now. Updates install when you restart the app. On Windows the update is the same unsigned installer, so SmartScreen may ask again. Your coworkers, chats and settings are kept across updates.

Troubleshooting

A coworker stays at "working" and never answers

On the free model this is almost always OpenCode's free usage limit for that model (see First launch). Press Stop, then either try again later, switch the coworker's model, or connect another provider. If it happens on Claude, ChatGPT or Google Antigravity, check the provider's status page and that its CLI still works in a terminal.

"Sign in required" for Claude or ChatGPT

Run claude auth login or codex login in a terminal, sign in, then click Check again in Settings, AI and models, or restart Sahkarmi. Sahkarmi only uses the CLI's own login; it cannot sign in for you.

"Could not start" next to a provider

The CLI was found but did not start. Run claude --version or codex --version in a new terminal to see the real error. If the CLI is installed in an unusual place, start Sahkarmi with SAHKARMI_CLAUDE_PATH or SAHKARMI_CODEX_PATH set to the executable's full path.

AI updates shows "Could not update" after a download

In 0.7.1 a leftover temporary folder on Windows can show this message even though the runtime was installed. Restart Sahkarmi; if the version under Settings, Updates is the new one, ignore the message. Fixed in the next release.

SmartScreen or Defender blocks the installer

Choose More info, then Run anyway. The installer is unsigned, not malicious; verify its checksum against the release page if in doubt. Do not disable Defender.

Where are the logs?

Windows: %APPDATA%\Sahkarmi\logs\sahkarmi.log. macOS: ~/Library/Application Support/Sahkarmi/logs/sahkarmi.log. Linux: ~/.config/Sahkarmi/logs/sahkarmi.log. Settings, Data & privacy, Export diagnostics produces a redacted bundle with versions and capability states and no conversation content. Before sharing a log publicly, remove anything personal: it can contain the email address of a connected provider account.

Something else

Open an issue at github.com/ganguydhrubo/sahakarmi/issues with the app version (Settings, About), your operating system, the provider in use and the steps to reproduce. Never paste tokens, ~/.codex, ~/.claude or conversation contents.

Uninstall and remove data

Windows

Settings, Apps, Installed apps, Sahkarmi, Uninstall (or run Uninstall Sahkarmi.exe in the install folder). This removes the program only. To also remove your data, delete %APPDATA%\Sahkarmi (coworkers, chats, settings, browser profile), %LOCALAPPDATA%\sahkarmi-updater (downloaded updates) and the Sahkarmi folder in your user profile (coworker workspaces, Shared files, Downloads).

macOS

Move Sahkarmi out of Applications. Data lives in ~/Library/Application Support/Sahkarmi and ~/Sahkarmi.

Linux

Delete the AppImage. Data lives in ~/.config/Sahkarmi and ~/Sahkarmi.

Sahkarmi never touches ~/.codex or ~/.claude; those belong to the Codex and Claude CLIs. There is no Sahkarmi cloud account to close because none exists.
